# AGENTS.md

## Назначение файла

Этот документ — инструкция для AI-ассистентов, которые помогают разрабатывать и поддерживать проект **Home**. Здесь описаны архитектура, стек, соглашения по коду и правила работы с проектом. Любое изменение должно соответствовать этому документу.

## Общие правила

1. **Не изобретай лишнего**. Если задачу можно решить стандартными средствами Angular / PrimeNG / Tailwind / Supabase — делай так.
2. **Соблюдай модульную структуру**. Каждый модуль приложения живёт в `src/app/features/<module-name>/`.
3. **Не ломай существующий функционал**. Если добавляешь новое, проверь, что старое работает.
4. **Пиши чистый TypeScript**. Избегай `any`. Используй строгую типизацию.
5. **Русский язык интерфейса**. Все пользовательские тексты — на русском.
6. **Дизайн-система**:
   - Primary: `#C26D55`
   - Secondary: `#8FA18B`
   - Tertiary / фон: `#F9F6F0`
   - Neutral (текст): `#2D2D2D`
   - Стиль: Material Design.
7. **PWA-first**. Приложение должно корректно работать на мобильных устройствах, планшетах и десктопе.
8. **Тема**. Поддержка светлой/тёмной темы через настройки пользователя и CSS-переменные.

## Технический стек

- **Angular v22**
- **PrimeNG** — UI-компоненты (кнопки, формы, диалоги, таблицы и т.д.)
- **Tailwind CSS** — утилитарная стилизация, кастомные цвета через `tailwind.config.js`
- **Supabase**:
  - Auth — авторизация
  - Postgres — база данных
  - Realtime — живые обновления (опционально)
  - Storage — хранение фото
  - Edge Functions — push-уведомления
- **RxJS** — реактивное состояние
- **Angular PWA** — service worker, манифест

## Соглашения по коду

### Компоненты

- Используй standalone-компоненты Angular (не нужно писать standalone: true - это задано по умолчанию).
- Название файла: `<name>.component.ts`.
- ChangeDetection: `OnPush` по умолчанию.
- Крупные формы выноси в отдельные компоненты.

### Сервисы

- Сервисы данных называй `<entity>.service.ts` (например, `dishes.service.ts`).
- Все вызовы Supabase инкапсулируй в сервисах слоя `data/`.
- Используй `signal` или `Observable` для состояния — единообразно в рамках модуля.

### Модели

- Все сущности БД должны иметь TypeScript-интерфейс в `models/`.
- Название интерфейса: `Dish`, `FridgeItem`, `CleaningTask` и т.д.
- Для полей `repeat_config`, `visible_tabs` и других JSONB используй конкретные типы, не `any`.

### Стили

- Предпочитай Tailwind-классы кастомным CSS.
- Кастомные цвета проекта должны быть в `tailwind.config.js` и/или CSS-переменных PrimeNG.
- Для медиа-запросов используй Tailwind-брейкпоинты: `sm`, `md`, `lg`, `xl`.

### Роутинг

- Каждый feature-модуль экспортирует свои роуты.
- Главный роутер (`app.routes.ts`) лениво загружает модули.
- Защищай приватные роуты `AuthGuard`.

## Работа с Supabase

### Авторизация

- Используй `supabase.auth` из `SupabaseService` в `core`.
- После логина загружай профиль пользователя и сохраняй в сервисе/сигнале.

### База данных

- Не пиши SQL-запросы напрямую из фронтенда. Используй Supabase Client.
- Для сложных выборок используй RPC ( Supabase Functions ) или представления (views).
- Всегда учитывай RLS-политики.

### Фото

- Загрузка фото через `ImageUploaderComponent`.
- По умолчанию фото хранятся в Supabase Storage.
- URL фото сохраняется в БД как строка.
- Конфигурация хранилища вынесена в `environment.ts`.

### Push-уведомления

- Подписки хранятся в `push_subscriptions`.
- Отправка через Edge Function `send-push`.
- Запрос разрешения на push — только после явного включения в настройках.

## UI/UX-правила

### Адаптивность

- Mobile-first подход.
- На мобильном: нижний таб-бар, полноэкранные формы, карточки в одну колонку.
- На десктопе: боковое меню, модальные окна, карточки в 2–3 колонки.

### Формы

- Используй `ReactiveFormsModule`.
- Валидация с понятными русскими сообщениями об ошибках.
- Кнопка сохранения отключена, пока форма невалидна или не изменилась.

### Списочные экраны

- Пустое состояние — всегда с иконкой и поясняющим текстом.
- Поиск и фильтры — в верхней части экрана.
- Загрузка — скелетоны PrimeNG.

### Диалоги

- Подтверждение удаления — всегда через `ConfirmDialog`.
- Успешное действие — тост `p-toast`.

## Добавление нового модуля

1. Создай папку в `src/app/features/<module-name>/`.
2. Добавь `models/<model>.ts` для всех сущностей.
3. Добавь `data/<model>.service.ts` для работы с Supabase.
4. Создай компоненты списка, детали и формы (если нужно).
5. Опиши роуты в `<module>.routes.ts`.
6. Добавь пункт в меню/навигацию.
7. Добавь модуль в список настраиваемых вкладок (`settings`).
8. Обнови `README.md` и `AGENTS.md` при необходимости.
